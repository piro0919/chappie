# Rust Backend Modules (`src-tauri/src/`)

Per-module reference. Kept out of [CLAUDE.md](../../CLAUDE.md) so the top-level guide stays scannable; refer here when working in a specific Rust module or wiring a new Tauri command.

When you add or significantly change a module, update the matching entry here and the architecture summary in CLAUDE.md.

## Core / wiring

- `lib.rs` — main: Builder, plugin registration, tray init, Tauri commands (`set_tray_state`, `open_settings`, `ensure_model`, `ensure_speaker_model`, `speaker_is_enrolled` / `speaker_clear_enrollment` / `speaker_enroll`, `start_enrollment_recording` / `finish_enrollment_recording`, mic permission, `start_listening`/`stop_listening`/`pause_listening`/`resume_listening`, `chat_complete`, `is_muted`, `hud_show`/`hud_dismiss`, `set_update_available`). `speaker_enroll` chunks the recorded buffer into 3s windows with 2s stride, L2-normalises each embedding, and averages into a centroid before persisting. Hides the Dock icon (`ActivationPolicy::Accessory`); blocks duplicate launches via `tauri-plugin-single-instance`. Hosts `run_whisper(audio: Vec<f32>) -> Result<String, String>` used by the in-process audio pipeline.
- `tray.rs` — menu-bar tray icon (5 states: idle/listening/thinking/speaking/error + a separate "off" icon when the user disables mic). Menu items: status, mic on/off check item, 設定を開く, アップデートを確認, 終了. Toggling mic off actually drops the cpal stream so macOS no longer reports Chappie as a mic-using app. Settings window comes to the front via `NSApp.activateIgnoringOtherApps:` since Accessory-mode apps don't auto-focus. Holds `UPDATE_AVAILABLE: AtomicBool` — the `timer.rs` ticker reads it to prefix the tray title with `🔔` until the next successful update.
- `updater.rs` — Rust-side auto-update flow using `tauri-plugin-updater` + `tauri-plugin-dialog`'s `blocking_show()` so the dialog is window-independent (JS `ask()` would attach to the hidden main window as a sheet). Three trigger types: `Launch` (startup, auto-prompts if update found), `Periodic` (6h background ticker, only flips the tray 🔔 badge — never interrupts), `Manual` (tray "アップデートを確認" menu, always shows result including "you're up to date"). Mirrors Galopen's pattern.
- `i18n.rs` — global `Lang` enum (ja/en/es/fr/de/zh/pt/ko/it) backed by a `Mutex<Lang>`. `set_app_language` Tauri command updates it and re-applies the tray; `tray.rs` / `updater.rs` / `capabilities.rs` branch on `current()`.
- `log_event.rs` — `linfo!` / `lwarn!` / `lerror!` macros that both eprintln and emit a `log` event so the renderer's `lib/log-bridge.ts` can mirror Rust logs into the Web Inspector console.

## Audio + speech

- `audio.rs` — cpal-based mic capture on a dedicated OS thread → mono f32 → rubato resample to 16kHz → **WebRTC APM** (AGC + NS + HPF, skipped during barge-in to avoid amplifying TTS echo) → Silero VAD on 512-sample frames → RMS gate → **speaker gate** (only when enrolled) → Whisper → emit `speech` (or `speech-bargein` for echo-tagged segments) event. `pause_listening` / `resume_listening` flip a global `MUTED` flag for transient TTS-time muting; the tray-driven mic on/off goes through `start_listening` / `stop_listening` instead so the cpal stream is fully released. Also hosts the enrollment recording path: `start_enrollment_recording` / `finish_enrollment_recording` route post-APM samples into `ENROLLMENT_BUF` while skipping VAD / wake-word, and emit `speaker_enroll:level` (~20 Hz RMS) so the Settings UI can render a live amplitude meter.
- `apm.rs` — thin wrapper around the `webrtc-audio-processing` crate (`bundled` feature, requires `meson` + `ninja` to build). Builds a 16 kHz mono APM with **AGC2** (`adaptive_digital: Some(AdaptiveDigital::default())` — without this the gain controller is effectively a no-op), **NoiseSuppression at High**, and **HighPassFilter**. AEC is intentionally **off** (the speaker-recognition gate covers external audio that AEC can't, like a TV across the room). 10ms / 160-sample frames; the segmenter feeds it post-resample audio before VAD.
- `speaker.rs` — opt-in voice biometrics. Holds the ECAPA-TDNN ONNX model in a global `OnceLock<Option<Model>>` (lazy-loaded; missing file does NOT poison the lock so a later enroll can re-attempt). `ensure_model` streams the ONNX from Hugging Face to `~/.chappie/models/voxceleb_ECAPA512_LM.onnx` with `speaker_model:progress` events. `compute_embedding` builds 80-dim mel fbank (kaldi-compatible, 25ms / 10ms, hamming window) → tract ONNX inference → 192-dim L2-normalised embedding. `save_enrollment` persists the averaged centroid (after L2-norm + mean across 3s windows / 2s stride) to `~/.chappie/voice.bin` (192 × f32 LE). `score_against_enrolled` computes cosine similarity; if it's below `ENROLL_THRESHOLD = 0.40` the segmenter drops the segment before Whisper.
- `model.rs` — auto-downloads the Whisper model (`ggml-small.bin`) into `~/.chappie/models/`. Streams via `reqwest`, emits `model:progress` and `model:ready` events.

The Whisper context lives globally in `OnceCell<Mutex<WhisperContext>>`. Whisper's language hint is held in a separate `Mutex<Option<&'static str>>` and is updated by the renderer via `set_whisper_language` whenever the user changes language in Settings.

## LLM + tools

- `openai.rs` — `chat_complete(api_key, model, mode, messages, on_chunk)` Tauri command. **Free / Pro modes** (`mode == "free" | "paid"`) load `~/.chappie/device-id` and dispatch via `llm/proxy_impl.rs` to the chappie.kkweb.io proxy with `X-Chappie-Device-Id`; when a subscription token is present it is forwarded so the proxy can bypass the daily cap for Pro users. The renderer is responsible for only emitting `"paid"` when the user has an active subscription — see `resolveMode` in `settings.ts`. **BYOK** auto-detects the provider from the API key prefix (via `provider.rs`) and routes: OpenAI uses chat/completions; Anthropic and Gemini delegate to dedicated modules. Streams via SSE through a `Channel<String>` so the renderer can begin TTS on the first sentence. Multi-round tool calling with marker-tool round-skip. The renderer never touches the API key in HTTP code. Tools available: `end_conversation`, `get_current_time`, `set_timer` / `list_timers` / `cancel_timer`, `add_reminder_at` / `list_reminders` / `cancel_reminder`, `open_url`, `open_youtube` / `close_youtube`, `web_search`, `get_weather`, `open_app`, `open_finder`, `get_volume` / `set_volume` / `set_mute`, `control_music` / `get_now_playing`, `get_battery_status`, `read_clipboard` / `write_clipboard`, `take_screenshot`, `add_note` / `list_notes` / `delete_note`, `save_memory` / `recall_memory` / `list_memories` / `forget_memory`, `lock_screen`, `set_sleep_prevention` / `get_sleep_prevention`, `list_events` (today/tomorrow/upcoming, EventKit read-only), `list_capabilities`, MCP-contributed tools (currently `mcp_news_latest`). `set_mute` also pushes a brief HUD ("🔇 ミュート" / "🔊 ミュート解除").
- `gemini.rs` — Google Gemini chat completion. Separate module because the wire format is different (roles user/model, system_instruction hoisted, tools as function_declarations, functionCall / functionResponse parts, key as ?key= query param, `:streamGenerateContent?alt=sse`). Reuses `openai::execute_tool` and `openai::all_tools()` so tools are defined once.
- `anthropic.rs` — Anthropic Messages API. Separate again: x-api-key header + anthropic-version, system field hoisted, content blocks (text / tool_use / tool_result) instead of plain string content, typed SSE events (content_block_start / content_block_delta with input_json_delta / message_delta), max_tokens required. Reuses `openai::execute_tool` and `openai::all_tools()`.
- `provider.rs` — auto-detects the LLM provider from the API key prefix (`sk-` → OpenAI, `sk-ant-` → Anthropic, `AIza` → Gemini). Returns `Option<Provider>` so unknown prefixes (xAI / OpenRouter / unrecognized) surface as a clear error rather than silently falling back. Holds each provider's base URL and default model.
- `llm/proxy_impl.rs` — `ProxyProvider` for Free mode. Composes `GeminiProvider` to reuse the entire Gemini wire format (request body, SSE parsing, tool round-trip); only `endpoint` (proxy URL), `apply_auth` (device-id header), and `label` differ. The trait's `api_key` slot carries the device id. Proxy URL overridable via `CHAPPIE_PROXY_URL` env (default `https://chappie.kkweb.io/api/chat`).
- `device_id.rs` — `~/.chappie/device-id` file used in Free mode as the proxy quota key (`X-Chappie-Device-Id` header). On fresh installs, derived deterministically on macOS via `UUIDv5(NAMESPACE, IOPlatformUUID)` (via ioreg) so deleting the file no longer resets the quota — the next launch re-derives the same id. Existing v4 ids from older installs are kept as-is to avoid a one-time quota reset on upgrade. Non-macOS and the `ioreg`-unavailable case fall back to a stored v4. The UUIDv5 path is one-way (SHA-1-based) so the raw hardware UUID never leaves the machine. Cross-device quota still arrives with Phase 3 auth — this is hardening, not a replacement.
- `capabilities.rs` — single source of truth for the `list_capabilities` self-introduction tool. When you add a new tool, also add a matching short example here so users can discover it just by asking "何ができるの？".
- `mcp.rs` — MCP-style tool registry. v1 servers are in-process Rust modules that expose an MCP-shaped surface (`tools_openai_schema()` + async `try_execute(name, args)`); the abstraction is intentionally MCP-compatible so individual servers can later be swapped for stdio JSON-RPC subprocesses without touching `openai.rs` / `anthropic.rs` / `gemini.rs`. Tool naming is `mcp_<server>_<tool>` so dispatch routes by prefix and MCP tools cannot collide with native ones. Currently hosts the `news` server (`mcp_news_latest`, RSS-backed: NHK 主要 / Hacker News / BBC World).
- `tool_usage.rs` — lightweight per-tool invocation counter persisted to `~/.chappie/tool_usage.json` (`{ tool_name: { count, last_used_at_unix_ms } }`). `record(name)` is called from the top of `tools::execute_tool` so every native + MCP tool dispatch is counted via a single code path. Exposed to the renderer via the `list_tool_usage` Tauri command. Purpose: surface which of the 38+ tools are actually used so the kitchen-sink can be pruned with data instead of guessing.

## Long-term memory (experimental, opt-in)

- `memory.rs` — long-term memory store persisted to `~/.chappie/memory.json`. Distinct from `notes.rs`: notes are verbatim user-dictated text, memories are LLM-curated facts about the user (`profile` / `preference` / `episode` kinds). `save_memory(text, kind)` dedupes on case-fold equality; `recall_memory(query, limit)` scores entries by char-bigram overlap (handles JP without word breaks) plus a small recency bonus and bumps `last_recalled_at` so frequently-used entries float up; `list_memories(kind?, limit)` returns newest-first; `forget_memory(id)` removes. `profile_summary()` returns a short bullet list of profile + preference entries that gets injected as a `system` message in all 3 providers' chat_complete paths (after the persona prompt to keep the prompt-cache prefix stable). Episodes are NOT included in profile_summary — they surface only via `recall_memory` to keep the always-on prompt size bounded.
- `session_log.rs` — **L1 layer** of the conversation-memory stack. Append-only `~/.chappie/log/YYYY-MM-DD.jsonl` of every user/assistant turn, written from the success path of all 3 provider modules. Each `append_turn` also calls `rag::index_turn` so the new turn becomes recall-able without a restart. Separate from `memory.rs`: the jsonl is the raw conversational substrate that summarizer / topics derive from, while memory.json is the LLM-curated fact store.
- `embedding.rs` — local ONNX embedding via [multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small) (384-dim, 100+ languages including all 9 Chappie locales; ~470 MB fp32). Mirrors `speaker.rs`'s `OnceLock + ensure_model` pattern with its own progress events (`embedding_model:progress` / `:ready`). **Critical implementation note**: tract's `into_optimized()` is run on the *typed* graph with the model's original symbolic seq_len, NOT a fixed-padded shape. An earlier fixed-padding attempt yielded near-identical (cosine ≈ 0.9998) embeddings across all inputs because tract's optimizer didn't honor attention_mask under fixed seq_len; symbolic shape preserves masking and gives meaningful similarities (~0.86 same-topic / ~0.78 cross-topic on the smoke test data in `tests/rag_smoke.rs`).
- `rag.rs` — **L1 retrieval**. In-memory `Vec<IndexedTurn>` populated on startup from all `~/.chappie/log/*.jsonl`; per-day embedding cache lives at `~/.chappie/log/<date>.emb.bin` (8-byte ts + 384×f32 records, append-only). `recall(query, k)` does linear cosine over the index, **excludes the last 7 days** (covered by L2), and filters at similarity ≥ 0.75. `recall_prompt(query, 3)` is injected into all 3 provider system prompts right after L2. `index_turn` is called from `session_log::append_turn` to keep new turns recall-able without a restart.
- `summarizer.rs` — **L2 layer**. Lazy daily summaries persisted to `~/.chappie/summaries/<date>.json`. `maybe_backfill(api_key)` fires once per process from each chat_complete entry point and walks the past 7 days of session logs, generating missing summaries via the same LLM provider as chat (auto-detected from key prefix). `recent_summaries_prompt(7)` formats the past week's summaries for injection between `profile_summary` and the L1 RAG block. Also hosts `complete_oneshot` — a shared non-streaming one-shot completion helper that `topics.rs` reuses.
- `topics.rs` — **L3 layer**. Longitudinal topic / preference extraction from the past 30 days of summaries, refreshed weekly (or when the file is older than 7 days). `maybe_refresh(api_key)` follows the same once-per-process pattern as the summarizer; the result is persisted as `~/.chappie/topics.json` and surfaced via `prompt_section()` which injects right after `memory::profile_summary()` (most cache-stable position).

## Tools / system integration

- `notes.rs` — voice memo store persisted to `~/.chappie/notes.json`. `add_note(text)` appends; `list_notes(query?, limit)` does case-fold substring filter, newest first; `delete_note(id)` removes. Lazy-loaded on first access. Embedding/RAG can layer on later if recall quality drives it.
- `volume.rs` — system audio volume helpers via `osascript -e "set volume output volume N"` / `output muted`. Exposes `is_muted` Tauri command for the renderer to branch its TTS pipeline.
- `music.rs` — Spotify / Apple Music control via osascript (`playpause` / `next track` / `previous track`) and now-playing readout. Only acts on apps that are already running so a casual "play" never silently launches Spotify; auto mode prefers Spotify, falls back to Music.
- `clipboard.rs` — `arboard` wrapper for `read_clipboard` / `write_clipboard` tools.
- `screenshot.rs` — `screencapture(1)` wrapper for `take_screenshot`. `selection`/`fullscreen` × `clipboard`/`file (~/Desktop/Screenshot YYYY-MM-DD HH.MM.SS.png)`. Runs in `spawn_blocking` so interactive selection doesn't stall the runtime; cancellation (Esc) is detected by missing output file in file mode.
- `battery.rs` — parses `pmset -g batt` to surface percent / charging state / time-remaining / power source. Returns `has_battery=false` on desktop Macs without a battery.
- `power.rs` — `lock_screen` tool with three modes: `lock` (CGSession -suspend → login screen, system stays awake), `display_off` (`pmset displaysleepnow`), `sleep` (`pmset sleepnow`).
- `caffeinate.rs` — manages a child `caffeinate -d -i -m` process for `set_sleep_prevention` / `get_sleep_prevention`. Single global slot; calling `start` again replaces any existing one. Optional duration_minutes uses caffeinate's `-t`. Auto-cleared when the child exits (timer elapsed).
- `calendar.rs` — read-only macOS Calendar access via EventKit. Owns an `EKEventStore` on a dedicated OS thread (not Send/Sync) with mpsc command routing and `panic::catch_unwind` + `objc2::exception::catch` guards (same rule as `mic_permission.rs`). Exposes `list_events(range)` to the LLM with `today` / `tomorrow` / `upcoming` (next 7 days, top 10). Permission flow always calls `requestFullAccessToEvents`, never short-circuits on cached status.
- `finder.rs` — `open_finder` tool. Resolves keywords (downloads / desktop / documents / applications / trash / etc., plus their Japanese aliases) and literal paths (with `~/` expansion) and opens them via macOS `open`.
- `timer.rs` — in-memory tokio-based timer manager. `set_timer` schedules with `tokio::spawn`; on fire emits `timer:fired` and the renderer announces via TTS (or HUD if muted). Also runs `start_tray_title_ticker` — a 1Hz task that finds the soonest-firing timer, formats `M:SS`, and updates the tray title (combined with `🔔` if `UPDATE_AVAILABLE`).
- `reminder.rs` — absolute-time reminders persisted to `~/.chappie/reminders.json`. Distinct from `timer.rs` because reminders ("明日7時") must survive app restart while timers ("3分後") are intentionally ephemeral. Each reminder carries a `recurrence` field (`once` / `daily` / `weekly` / `monthly`); the scheduling task loops for recurring kinds, computing the next fire time after each emit via local-tz arithmetic (DST-safe; `chrono::Months` for monthly so end-of-month days roll back like Jan 31 → Feb 28). `init` on startup drops past-due one-shots and rolls past-due recurring reminders forward to their next fire after now (so 「毎朝 7 時」 doesn't silently die if the app was shut down past 7am). Fires `reminder:fired` (separate event) so the renderer can phrase it as "○○の時間です" rather than the timer's "○○のタイマーです".

## Windows + UI surfaces

- `hud.rs` — runtime-built always-on-top transparent HUD window (label `hud`, frameless / mouse passthrough). `show(app, text, duration_ms)` repositions it bottom-center on the monitor under the cursor, then emits `hud:show` for the renderer to fade the message in/out. Used as the visual fallback whenever the audio channel is unreliable (system mute) or worth reinforcing (mute toggles, timer fires).
- `miniplayer.rs` — runtime-built always-on-top webview window (label `miniplayer`) for voice-launched YouTube viewing. Distinct from HUD: decorated, mouse-interactive, persistent, anchored bottom-right of the cursor's monitor. Loads the target URL directly via `WebviewUrl::External` (no chappie renderer in the loop) so YouTube's own player UI is what the user sees. `show_youtube(app, query)` accepts a search keyword, full URL, or 11-char video id and routes accordingly; `hide(app)` dismisses. Reuses any existing window via in-page `window.location.href` navigation so user-dragged positions survive subsequent calls.

## macOS permission glue

- `mic_permission.rs` — `AVCaptureDevice.requestAccessForMediaType:` via objc2 + block2. **Always invokes requestAccess regardless of cached status** (cached status can be wrong for ad-hoc signed apps). Mirrors Galopen's calendar permission pattern.
- `screen_permission.rs` — `SCShareableContent.getShareableContentWithCompletionHandler:` from ScreenCaptureKit. Used because `CGRequestScreenCaptureAccess()` is synchronous and frequently never shows the dialog for ad-hoc signed apps. The async completion-handler pattern matches mic_permission and reliably triggers the system TCC prompt. Required for `take_screenshot`'s fullscreen mode (selection mode `-i` works without).
- `location_native.rs` — macOS CoreLocation wrapper for higher-precision geolocation. Mirrors `calendar.rs`: dedicated OS thread + mpsc command routing + `panic::catch_unwind` + `objc2::exception::catch` guards. Uses polling instead of a declare_class delegate — kick off `requestWhenInUseAuthorization` / `startUpdatingLocation`, then iterate `CFRunLoopRunInMode` in 100 ms ticks while checking `authorizationStatus` / `manager.location`. Best-effort reverse geocoding via `CLGeocoder.reverseGeocodeLocation:completionHandler:` (also block-based with runloop pumping). Exposes `check_permission` / `request_permission` / `get_location()` → `(lat, lon, locality?)`. Falls back to IP-based `location.rs` when not authorized or no fix within 10 s.
